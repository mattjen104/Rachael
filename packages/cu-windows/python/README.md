# `rachael-cu-windows` (Python sidecar)

Companion package for the TS [`@rachael/cu-windows`](../README.md) adapters.
Ships two services:

- **`rachael-cu-som`** — Set-of-Marks detector (OmniParser ONNX with an
  OpenCV heuristic fallback). Default port `8765`.
- **`rachael-cu-uia`** — Windows UIA bridge for the `WindowsUiaAdapter`.
  Wraps [`uiautomation`](https://pypi.org/project/uiautomation/) on Windows
  and is a no-op shim elsewhere (so the rest of the harness still imports
  cleanly on CI).

## Install

```bash
pip install "rachael-cu-windows[all]"
# or just the detector
pip install "rachael-cu-windows[detector]"
```

The OmniParser ONNX checkpoints are not vendored. Drop
`icon_detect.onnx` (and optionally `icon_caption.onnx`) into a `models/`
directory next to the service to enable the model path; otherwise the
service runs on the OpenCV heuristic detector.

## Run

```bash
rachael-cu-som          # listens on 127.0.0.1:8765
rachael-cu-uia          # listens on 127.0.0.1:8766 (Windows only)
```

Both services bind to `127.0.0.1` by default. Override with
`SOM_DETECTOR_HOST=0.0.0.0` (not recommended) or run them inside a
local-only Docker network.

## Schema validator

`rachael_cu_windows.schema` exposes pure-Python validators that mirror the
Zod schemas in `@rachael/cu-core`:

```python
from rachael_cu_windows.schema import validate_action, validate_observation

validate_action({"verb": "Click", "target": {"kind": "selector", "css": "button"}})
```

This is the boundary contract used by every Python-side caller (UIA bridge,
SoM detector tests, OSWorld harness adapters). It is regenerated by
`scripts/codegen-python-schema.ts` whenever the TS Zod schemas change.
